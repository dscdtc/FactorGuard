## 1. 产品摘要

### 1.1 一句话定位

> **FactorGuard 是独立于回测平台的因子质量检查与验真层。**

### 1.2 用户价值

> 回测告诉用户因子过去表现如何，FactorGuard 告诉用户这个结论是否经得起质疑。

### 1.3 核心问题

现有因子平台通常能够计算 IC、分组收益、换手、收益曲线和中性化结果，但用户仍然难以判断：

- 因子是否使用了未来数据；
- 财务或行情字段在测试时点是否真实可用；
- 好结果是否主要来自小微盘、行业或低流动性暴露；
- 结论是否只由少数年份、股票或极端样本贡献；
- 因子是否只是已有因子的改名或单调变换；
- 更改股票池、数据延迟或预处理后是否立即失效；
- 报告中的结论是否能够被其他人重新运行和验证。

FactorGuard 不以生成更多因子为核心，而是把因子研究结论转化为可检查、可反驳、可复现的证据对象。

## 2. 已确认决策、假设与冲突

### 2.1 已确认决策

- 首要用户是个人量化研究者，后续可能扩展到小型团队；
- 第一版聚焦 A 股日频因子；
- 项目首先服务黑客松展示，同时考虑后续商业化；
- 数据优先使用 TuShare 及其他合法免费数据源；
- AI 真实参与因子标准化和证据解释；
- 所有统计计算、压力测试和数值结果由确定性代码完成；
- 产品不提供策略组合、择时、荐股和自动交易；
- MVP 不执行用户上传的任意 Python 代码；
- 传统因子评估是完整产品的基础能力，不能因强调鉴证而缺失；
- 参考 Alphalens、Qlib 和 zer0factor 的指标体系与工程模式，优先复用成熟评估库；
- 大师方法拆解 Skill 进入 MVP，作为因子假设的结构化入口；
- 大师 Skill 不模拟人格、不输出大师策略，只拆解公开方法并鉴证代理因子。

### 2.2 暂定假设

- 提交截止日期按 2026年8月31日计算；
- 技术成员能够在两周内主要投入开发；
- 比赛允许联网调用模型 API；
- 演示现场可能出现断网或 API 不稳定，因此必须准备离线结果缓存；
- TuShare Token 至少能够访问部分行情和基础数据接口；
- 第一版不承诺完成财务公告时点鉴证；
- 第一版为单用户工作台，不建设登录、权限和团队空间。

### 2.3 当前冲突与处理原则

| 冲突 | 处理原则 |
|---|---|
| 免费数据与机构级可信要求冲突 | 显示数据完整度和限制，不做超出证据的承诺 |
| 1名技术成员与完整平台范围冲突 | 采用单体Python应用，冻结P0，取消非核心模块 |
| 通用Python输入与安全要求冲突 | 改为受限公式和标准因子值文件上传 |
| 30至50个完整因子与两周工期冲突 | 调整为8至12个正式因子和3个专用Demo |
| 因子排行榜与验真定位冲突 | 排行榜降为适用性视图，不作为首页主体验 |
| 大师方法与鉴证主线可能分裂 | 将大师方法做成结构化假设入口，统一进入评估与鉴证引擎 |

## 3. 产品目标与非目标

### 3.1 MVP目标

1. 用户能够在一个工作流中输入因子并获得完整鉴证报告；
2. 系统提供不低于主流因子分析工具的基础评估 Tear Sheet；
3. 系统能够稳定复现三个典型“好结果不可信”的Demo；
4. 用户能够通过大师方法拆解 Skill 将公开方法转为可验证因子假设；
5. 系统能够自动比较基线测试与多项反事实压力测试；
6. AI 只能引用确定性证据，不得编造任何指标；
7. 相同数据、因子和配置能够产生相同计算结果与证据哈希；
8. 评委能够在3分钟内理解传统评估、因子鉴证和大师方法拆解之间的关系。

### 3.2 非目标

MVP 不建设以下能力：

- 策略生成和多因子组合；
- 完整投资组合回测；
- 择时和个股买卖信号；
- 自动交易；
- 任意 Python 代码执行；
- 完整财务因子库；
- 因子商城；
- 用户账户、团队权限和在线协作；
- 实时行情和盘中计算；
- 健康度订阅与自动通知；
- 大规模云端任务调度；
- 机构级数据质量承诺。

## 4. 目标用户

### 4.1 核心用户画像

**个人量化研究者**

- 了解基本因子概念、IC和回测；
- 能阅读简单公式，部分用户会使用 Python；
- 从研报、社区、开源仓库或个人想法中获得因子；
- 缺少完整的数据工程和因子质量控制体系；
- 不愿为验证每个因子重复搭建大量检查脚本；
- 希望快速判断一个好结果是否值得继续研究。

### 4.2 核心用户任务

- “我看到一个表现很好的因子，想先判断它有没有明显错误。”
- “我修改了一个已有因子，想知道是否真正增加了新信息。”
- “我想确认因子效果是否只是来自小盘股或低流动性股票。”
- “我需要把研究配置和结论保存下来，之后能够重新运行。”
- “我希望AI解释结果，但不希望AI编造统计数字。”

### 4.3 后续团队用户任务

- 因子进入团队研究库前执行统一质量门禁；
- 比较因子不同版本；
- 保存审查人与审查记录；
- 共享私有因子凭证；
- 监控已通过因子的滚动衰减。

以上团队功能不进入本次MVP。

## 5. 产品叙事与竞争边界

### 5.1 统一叙事

```text
因子库 / 用户公式 / 因子值 / 大师方法拆解 Skill
                         ↓
                  标准化因子定义
                         ↓
           传统因子评估：完整基础能力
                         ↓
           对抗式鉴证：核心差异化能力
                         ↓
                可复现证据报告
```

四部分形成统一产品，不是四条独立产品线：

- 因子库提供经过标准化的研究对象；
- 传统因子评估提供用户熟悉的完整分析基线；
- 因子鉴证在基线之上主动寻找错误、脆弱性和公共暴露；
- 大师方法拆解 Skill 将公开思想转为待验证的因子假设，再进入同一评估与鉴证流程。

### 5.2 与现有平台的关系

FactorGuard 不替代聚宽、Qlib、zer0factor 或用户自己的研究代码，而是位于因子生成之后、进入正式因子库之前：

```text
研究平台 / 用户代码 / 研报方法
              ↓
       公式或因子值
              ↓
         FactorGuard
              ↓
当前支持 / 条件有效 / 脆弱 / 证据不足 / 无效
              ↓
   是否进入下一阶段研究
```

### 5.3 核心差异化

- 自动生成反事实测试，而不是只给出基线指标；
- 优先寻找结论可能出错的地方，而不是自动美化结果；
- 审计公式、数据时点、股票池、参数和结论的完整关系；
- 针对 A 股沉淀专项失效规则；
- 生成可以重新运行的证据凭证；
- AI 仅解释证据，不负责计算证据。

## 7. 信息架构与页面需求

### 7.1 页面一：鉴证工作台

**页面目标：** 让用户立即开始鉴证，而不是进入营销落地页。

**核心区域：**

- “新建鉴证”主操作；
- 最近运行列表；
- 三个问题因子Demo和一个大师方法Demo；
- 数据快照状态；
- 最近一次运行是否可复现。

**最近运行字段：**

- 因子名称；
- 运行时间；
- 总体结论；
- 关键风险；
- 数据版本；
- 查看报告操作。

**验收标准：**

- 用户从首页最多两次点击进入因子输入；
- 四个演示流程可直接载入，不需要重新配置；
- 没有数据时显示明确状态，不展示伪造示例指标。

### 7.2 页面二：因子输入与标准化

使用标签页切换以下方式：

1. 内置因子；
2. 文本描述；
3. 受限公式；
4. 上传因子值；
5. Python脚本（P2）；
6. 大师方法拆解。

#### 内置因子

MVP提前内置8至12个代表性因子及其完整评估结果，用户无需从零配置即可体验完整鉴证流程：

- 展示定义、预期方向、所需字段和可用时间；
- 问题Demo必须与正式因子明显区分；
- **预置评估结果：** 每个内置因子均附带预计算的完整传统评估 Tear Sheet、压力测试和鉴证报告，用户选择因子后可直接查看报告，无需等待计算；
- **预计算缓存策略：** 评估结果基于冻结的数据快照预计算，保证 `evidence_hash` 一致且可复现；
- **重新运行入口：** 预置结果页提供"重新运行"按钮，用户可修改参数（如时间范围、股票池、中性化方式）后触发新的计算；
- **因子分类展示：**
  - 价格与成交量类：动量、反转、换手率、波动率等；
  - 估值类：PE、PB、PS、股息率等（数据允许时）；
  - 质量类：ROE、毛利率、资产负债率等（数据允许时）；
  - 规模类：市值、流通市值等；
- 每个因子卡片显示：因子名称、类别、预期方向、最近一次评估结论、可复现状态；
- 问题Demo因子以警示图标和"含已知问题"标签在卡片上明确区分。

#### 文本描述

文本描述是因子导入的推荐方式，支持用户以自然语言或结构化描述定义因子：

- 用户以自然语言描述因子逻辑，包括数据字段、计算步骤、预期方向和适用条件；
- AI 将自然语言转换为 FactorSpec V2 结构化定义和受限公式；
- 系统标出歧义、缺失字段和时间假设；
- 用户必须确认 AI 生成的因子定义后才能运行；
- 用户可以直接编辑受限公式修正 AI 理解偏差；
- 文本描述支持 Markdown 格式，允许用户粘贴研报中的因子定义或公式文字说明。

#### 受限公式

受限公式提供安全的因子表达式编写能力：

- 用户直接输入符合受限公式语言规范的表达式；
- 公式通过解析器转换为抽象语法树，不允许调用 Python `eval`；
- 支持实时语法检查，即时提示错误位置和原因；
- 输入时自动补全可用字段和函数名；
- 与文本描述共享同一个确认流程，用户可随时切换回文本描述模式查看 AI 生成的公式解释。

#### 因子值上传

标准字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `trade_date` | 日期或YYYYMMDD | 是 | 因子观察日期 |
| `ts_code` | 字符串 | 是 | 股票代码 |
| `value` | 数值 | 是 | 因子值 |
| `factor_name` | 字符串 | 否 | 未提供时由用户填写 |

上传限制：

- 支持 CSV 和 Parquet；
- 默认最大文件50MB；
- `trade_date + ts_code` 必须唯一；
- 无穷值必须转为缺失并记录；
- 上传因子值但未提供公式时，系统必须显示"无法审计实现代码和未来引用"的限制。

#### Python脚本（P2）

Python脚本导入属于赛后规划，MVP不做代码执行，但预留UI入口和规范定义：

- **MVP占位：** 标签页显示"Python脚本"选项，以灰色标识"即将支持"，悬浮提示说明当前版本不执行任意Python代码；
- **规范预设：** 预定义因子计算脚本的标准接口规范，要求用户脚本必须实现 `compute_factor(data: pd.DataFrame) -> pd.Series` 函数签名；
- **安全策略：** 赛后通过沙箱环境执行用户脚本，限制文件系统访问、网络调用和系统命令；
- **输入输出约定：** 输入为标准化行情DataFrame，输出为因子值Series，索引为 `trade_date + ts_code` 组合键；
- **代码审查：** 系统自动检查脚本中是否使用未来数据、是否包含危险函数调用；
- 该功能进入P2后，脚本导入的因子与公式因子的评估和鉴证流程完全一致。

#### 大师方法拆解

- MVP内置一个“巴菲特公开质量框架”方法包；
- 展示公开方法来源，不模拟巴菲特人格；
- 将方法拆为资本回报、盈利质量、盈利稳定、财务安全和估值五类假设；
- 为每类假设映射一个或多个候选代理因子；
- 明确区分“原始思想”“可计算代理”和“代理局限”；
- 用户选择代理因子并确认后，进入与普通因子完全相同的传统评估和鉴证流程；
- 数据不足的代理必须显示“不可鉴证”，不得使用虚构数据补齐。

### 7.3 页面三：鉴证运行

**运行步骤：**

```text
输入检查
→ 数据对齐
→ 传统评估 Tear Sheet
→ 压力测试
→ 重复检测
→ 生成证据
→ AI解释
```

**交互要求：**

- 显示当前步骤和完成状态；
- 单项失败不应导致整个报告丢失；
- 关键数据缺失时停止相关测试并给出原因；
- AI接口失败时使用确定性模板完成报告；
- 已有相同运行哈希时允许直接读取缓存。

### 7.4 页面四：验真报告

报告使用标签页组织：

- 总览；
- 数据与时间质检；
- 传统评估；
- 压力测试；
- 重复性；
- 适用性；
- 复现凭证。

总览必须首先展示：

- 总体结论；
- 最严重问题；
- 当前证据支持什么；
- 当前证据不能证明什么；
- 推荐的下一项测试。

传统评估标签页必须提供用户熟悉的完整因子分析图表。总览不能以收益曲线作为唯一或首要结论，必须同时展示鉴证发现。

### 7.5 近期因子状态视图

该视图属于P1，参考用户提供的研报图片，但不制作简单排行榜。

每个因子至少展示：

- 近期原始表现；
- 市值中性化后表现；
- 历史分位；
- 置信区间或样本充分性；
- 数据风险和暴露风险标记。

行业TOP5表格改为“行业 × 因子”矩阵。颜色表示方向和强度，饱和度表示证据强弱，风险图标表示市值、流动性或极端样本问题。

### 7.6 市场切换

FactorGuard 设计为多市场通用平台，首发聚焦 A 股，但系统架构预留多市场扩展能力。

#### 支持的市场类型

| 市场 | 标识 | MVP状态 | 说明 |
|---|---|---|---|
| A股 | CN | 首发市场，完整支持 | 日频因子，沪深京三地 |
| 港股 | HK | UI入口占位 | 后续接入港股通或全港股 |
| 美股 | US | UI入口占位 | 后续接入NYSE、NASDAQ |

| 外汇 | FX | UI入口占位 | 后续接入主要货币对 |

#### MVP实现方式

- 工作台顶部提供市场选择器下拉菜单，默认选中"A股"；
- 非A股选项以灰色显示，悬浮提示"该市场数据即将支持"；
- 选择非A股市场时，页面显示引导性占位，不展示空数据或伪造指标；
- 市场切换器的设计风格与全局工具栏一致，不影响现有A股流程；

- 市场间因子对比和跨市场验证属于P2规划。

## 8. 标准化因子定义

### 8.1 FactorSpec V2

每个因子必须记录以下信息：

| 字段 | 说明 |
|---|---|
| `factor_id` | 稳定唯一标识 |
| `name` | 因子名称 |
| `version` | 因子版本 |
| `description` | 自然语言定义 |
| `formula` | 标准公式或空值 |
| `expected_direction` | higher或lower |
| `inputs` | 所需数据字段 |
| `frequency` | MVP固定为1d |
| `availability` | open、intraday、after_close等 |
| `availability_lag` | 数据额外延迟交易日数 |
| `min_window` | 最小回看窗口 |
| `universe_rule` | 股票池构建规则 |
| `preprocess` | 缺失、去极值、标准化方法 |
| `neutralization` | 无、市值、行业或组合 |
| `forward_periods` | 1日、5日、10日等 |
| `source` | 内置、用户、研报或上传文件 |
| `source_reference` | 来源说明 |

### 8.2 受限公式语言

MVP允许字段：

- `open`、`high`、`low`、`close`；
- `volume`、`amount`；
- `total_mv`、`circ_mv`、`turnover_rate`。

MVP允许函数：

- `delay(x, n)`；
- `ts_mean(x, n)`、`ts_sum(x, n)`、`ts_std(x, n)`；
- `rank_cs(x)`、`zscore_cs(x)`；
- `log(x)`、`abs(x)`；
- 基本四则运算。

公式必须通过解析器转换为抽象语法树，不允许调用 Python `eval`。

检查规则：

- `delay` 的窗口不得为负；
- 滚动窗口必须为正整数；
- 不允许访问白名单外字段和函数；
- 必须计算最长回看窗口；
- 必须检查除零、对数非正数和无穷值风险；
- 公式依赖的字段必须与 FactorSpec 声明一致。

## 10. 指标口径

### 10.1 时间约定

MVP内置日频因子默认在交易日 `t` 收盘后可用。

预测周期为 `h` 个交易日时，前瞻收益定义为：

```text
forward_return(t, h) = open(t + 1 + h) / open(t + 1) - 1
```

即因子在 `t` 日收盘后形成，最早从 `t+1` 日开盘开始观察未来收益。

如果用户声明不同可用时间，系统必须在报告中显示相应标签规则。

### 10.2 基线指标

| 指标 | 口径 |
|---|---|
| Daily IC | 每日因子值与前瞻收益的横截面Pearson相关 |
| Daily RankIC | 每日因子值与前瞻收益的横截面Spearman相关 |
| IC / RankIC Mean | 有效交易日IC或RankIC均值 |
| IC / RankIC Std | 有效交易日IC或RankIC标准差 |
| ICIR / RankICIR | `Mean / Std`，不年化值 |
| Annualized ICIR | `ICIR × sqrt(252)`，单独标记为年化 |
| t-stat与p-value | 日度IC均值的传统显著性参考，同时展示Bootstrap结果 |
| IC Positive Rate | 按预期方向调整后的IC或RankIC为正的日期占比 |
| Coverage | 有效因子值数量除以当日合格股票数量 |
| Quantile Returns | 各因子分组的平均前瞻收益 |
| Quantile Spread | 预期多头组与空头组的平均前瞻收益差 |
| Cumulative Quantile Returns | 各分组诊断收益的累计曲线 |
| Monotonicity | 分组序号与分组平均收益的Spearman相关 |
| Rolling RankIC | 默认63个交易日滚动RankIC均值 |
| Factor Return | 每日横截面回归中标准化因子暴露的收益系数 |
| Return Decay | 1日、5日、10日等不同预测周期的效果变化 |
| Top/Bottom Quantile Turnover | 两端分组相邻调仓日成员变化比例 |
| Factor Autocorrelation | 相邻日期因子横截面暴露相关性 |
| Gross Annualized Return | 分组或多空诊断收益的年化值 |
| Gross Volatility | 分组或多空诊断收益的年化波动 |
| Gross Sharpe | 未计交易成本的诊断Sharpe |
| Maximum Drawdown | 分组或多空诊断累计收益的最大回撤 |

每日计算 RankIC 的最低有效股票数默认为30。低于阈值的日期不参与汇总，并记录为样本不足。

### 10.3 传统评估 Tear Sheet

传统评估不能只保留几个摘要数字。MVP至少提供以下视图：

1. 因子值分布、缺失率和覆盖率；
2. IC与RankIC时间序列、分布和滚动均值；
3. 1日、5日、10日预测周期的IC衰减；
4. 五分组平均收益及分组单调性；
5. 五分组累计诊断收益曲线；
6. 多空分组价差及年度表现；
7. Top/Bottom分组换手率；
8. 因子自相关；
9. 原始因子与中性化因子的传统指标对比；
10. 样本量、统计显著性和Bootstrap置信区间。

实现优先复用 `alphalens-reloaded` 等成熟开源评估能力，再统一指标命名和数据口径。FactorGuard自研部分集中在时点质检、自动压力测试、证据模型和结果归因。

### 10.4 置信区间

- 默认使用按日期分块的 Bootstrap；
- 默认区块长度20个交易日；
- 默认重复500次；
- 默认固定随机种子并写入复现凭证；
- 输出 RankIC Mean 的95%置信区间；
- 样本不足时不输出显著性判断。

### 10.5 指标边界

- 所有收益指标只用于因子诊断，不表示可交易策略收益；
- 不因样本内 IC 为负而自动反转因子方向；
- 预期方向必须由用户或因子定义预先声明；
- 多预测周期分别出具证据，不合并为一个最好看的结果。
- 分组累计收益、Sharpe和最大回撤属于因子诊断指标，不代表可执行投资策略；
- 传统显著性检验可能受时间相关性影响，必须与分块Bootstrap结果共同展示。

## 11. 压力测试需求

### 11.1 数据延迟测试

- 将因子值整体延迟1个交易日重新计算；
- 有余力时增加2个交易日延迟；
- 比较方向、RankIC均值、置信区间和分组单调性；
- 延迟后明显失效时提示可能存在时点敏感或数据可用性问题。

### 11.2 剔除微盘测试

- 每个交易日按 `total_mv` 横截面排序；
- 剔除市值最低20%的股票；
- 使用相同参数重新计算指标；
- 如果历史市值不可用，则不运行并明确显示数据缺口；
- 不允许用当前市值代替历史市值。

### 11.3 市值中性化测试

- 每个交易日对因子值回归 `log(total_mv)`；
- 使用残差作为中性化因子；
- 比较中性化前后方向和有效性；
- 保存回归样本量和缺失情况。

### 11.4 极端贡献样本测试

- 计算标准化因子与标准化前瞻收益的绝对乘积；
- 剔除贡献最大的1%股票日期样本；
- 重新计算 RankIC 和分组表现；
- 判断结论是否集中依赖少量异常样本。

### 11.5 时间分段测试

#### 时间维度切换

用户可切换以下时间维度进行分段测试：

- **年维度（默认）：** 按自然年分段，展示每个年度的因子表现；
- **季度维度：** 按自然季度（Q1-Q4）分段，识别因子的季节性特征；
- **月度维度：** 按自然月分段，用于检测因子在特定月份（如财报季、年末效应）的稳定性；
- **自定义分段：** 用户可手动设定分段数量（如按固定交易日数等分）。

切换维度时，系统自动重新计算各分段的指标，并保持与基线测试相同的计算口径。

#### 时间范围切换

支持以下时间范围模式：

- **全量范围（默认）：** 使用全部可用数据；
- **近N年：** 如近3年、近5年，用于评估因子在近期市场环境中的有效性；
- **自定义起止日期：** 用户输入起始和结束日期，系统仅在该区间内执行测试，区间外数据不参与任何计算；
- **样本外预留：** 用户可指定最后一段数据作为"样本外"区间，该区间仅展示、不参与优化相关参数的计算。

切换时间范围后，所有评估指标（IC、RankIC、分组收益、压力测试等）均在指定范围内重新计算，并在报告中明确标注当前使用的时间范围。

#### 展示规则

- 默认按自然年展示；
- 低于60个有效交易日的分段不单独下结论；
- 展示方向一致性、RankIC和置信区间；
- 不自动将最好年份作为总体结论；
- 时间维度或范围切换后，所有关联图表和指标同步更新；
- 时间范围切换入口与时间维度选择器统一放置在传统评估和压力测试页面的顶部工具栏。

### 11.6 压力结果对比

每项压力测试输出：

- 基线指标；
- 压力后指标；
- 绝对变化；
- 方向是否保持；
- 置信区间是否包含0；
- 测试是否完成；
- 未完成原因；
- 对应证据ID。

当基线 `abs(RankIC Mean) >= 0.005` 时，可补充保留比例：

```text
retention_ratio = abs(stressed_rank_ic) / abs(baseline_rank_ic)
```

基线过小时不显示保留比例，避免产生误导性百分比。

## 12. 因子重复性检测

### 12.1 三层检测

1. **公式关系：** 标准化公式结构、窗口和单调变换关系；
2. **暴露相关性：** 每日横截面Spearman相关的时间均值；
3. **收益相关性：** 因子分组收益或因子收益序列相关性。

### 12.2 MVP默认阈值

阈值只用于提示，必须在界面公开：

| 条件 | 默认状态 |
|---|---|
| 暴露相关性绝对值低于0.80 | 未发现明显重复 |
| 0.80至0.95 | 高相似，需检查 |
| 高于或等于0.95 | 极高相似 |
| 极高暴露相关且收益相关高 | 疑似重复信息 |
| 公式等价或仅单调变换 | 公式重复 |

系统不得仅根据一个相关系数直接断言两个因子完全相同。

## 13. 适用性地图

### 13.1 P0维度

- 市值：大、中、小、微盘或分位分组；
- 时间：自然年或前后样本段；
- 流动性：数据允许时按成交额分组。

### 13.2 P1维度

- 行业；
- 牛熊环境；
- 高低波动环境；
- 宏观环境；
- 风格维度：成长/价值/平衡等风格因子分组。

### 13.3 多维度对比总览

适用性地图除展示单维度因子表现外，必须提供多维度交叉对比视图，帮助用户快速定位因子在不同场景下的差异化表现：

- **维度选择器：** 用户可自由选择2至3个维度进行交叉对比，例如"市值 × 成长/价值"或"时间 × 行业 × 流动性"；
- **主维度矩阵：** 以第一个维度为行、第二个维度为列，生成热力图矩阵，颜色表示因子RankIC方向与强度，饱和度表示证据充分度；
- **辅助维度切面：** 当选3个维度时，以第三个维度作为切面选择器，用户可切换不同切面查看矩阵变化；
- **对比基准：** 每个单元格标注该维度组合下的有效样本数、RankIC均值和置信区间，与全样本基线对比；
- **风格维度定义：**
  - 成长：高营收增速、高盈利增速、高研发投入等；
  - 价值：低PE、低PB、低PS、高股息率等；
  - 平衡：成长与价值特征不显著的中性区间；
  - 质量：高ROE、高毛利率、低杠杆等（数据允许时）；
- **预警标记：** 当因子在某个维度组合下方向翻转或显著性消失时，该单元格以红色边框标记，提示用户注意适用边界。

### 13.4 展示规则

- 颜色表示方向和效果；
- 饱和度表示证据充分程度；
- 单元格同时显示有效日期数；
- 样本不足显示空白或"证据不足"，不能显示为0；
- 点击单元格查看原始指标和压力测试结果；
- 多维度对比视图中，支持导出当前维度组合的矩阵快照。

## 14. 证据等级与总体结论

### 14.1 五个证据维度

FactorGuard 不使用不透明的综合分数。报告展示以下维度：

| 维度 | 检查内容 |
|---|---|
| 数据完整性 | 覆盖率、缺失、股票池、字段可用性 |
| 时间正确性 | 未来引用、观察时点、收益标签、数据延迟 |
| 统计支持 | 方向、RankIC、置信区间、单调性和样本量 |
| 压力稳健性 | 微盘、中性化、延迟、极端样本和时间分段 |
| 信息独立性 | 公式、暴露和收益相关性 |

每个维度显示：`通过`、`存疑`、`失败`或`未测试`。

### 14.2 总体结论

| 结论 | MVP规则 |
|---|---|
| 无效 | 存在未来引用、严重标签错位或关键数据错误 |
| 证据不足 | 样本不足、置信区间包含0或关键测试缺失 |
| 脆弱 | 基线有效，但多个核心压力测试方向翻转或显著衰减 |
| 条件有效 | 仅在明确市值、时间或流动性环境中获得支持 |
| 当前支持 | 无关键错误，方向符合预期，统计证据和核心压力测试均支持 |

“当前支持”不表示因子未来一定有效，报告必须固定显示该限制。

## 15. AI功能与确定性代码边界

### 15.1 AI负责

- 将自然语言转换为 FactorSpec V2 和受限公式；
- 识别公式描述中的歧义；
- 将有来源的公开大师方法拆解为原则、假设和候选代理因子；
- 解释代理因子与原始思想之间的距离和局限；
- 根据证据ID解释质检和压力测试结果；
- 比较相似因子的实际区别；
- 总结当前证据支持与不支持的结论；
- 推荐下一项诊断测试。

### 15.2 AI不负责

- 读取原始行情后自行计算指标；
- 生成或修改 IC、收益、相关性和置信区间；
- 自动改变因子方向以获得更好结果；
- 模拟大师人格、语气或虚构大师观点；
- 把粗糙代理因子描述成大师原始思想本身；
- 在证据不足时推断因子有效；
- 输出买卖信号或投资建议。

### 15.3 AI输入输出契约

AI接收结构化证据摘要，不直接接收无约束的全量计算环境。

建议输出结构：

```text
summary
findings[]
  - severity
  - claim
  - evidence_ids[]
limitations[]
next_test
```

系统要求：

- 每条 finding 至少引用一个证据ID；
- 找不到证据的 finding 不展示；
- 精确数字由确定性渲染器从证据记录插入；
- 模型调用失败时使用确定性模板报告；
- 模型供应商通过配置切换，不建设多Agent流程；
- 不在日志中保存API密钥。

## 16. 大师方法拆解 Skill

### 16.1 产品定义

大师方法拆解 Skill 是产品内的 AI 工作流，不是独立产品，也不是人格化 Agent。它负责把有公开来源的方法论转换为可以进入传统评估和因子鉴证流程的结构化假设。

其价值不是告诉用户“大师会买什么”，而是回答：

- 公开方法中包含哪些可检验命题；
- 哪些数据指标可以作为代理；
- 这些代理与原始思想之间有多大距离；
- 每个代理因子在A股历史数据中是否得到支持；
- 数据不足时哪些命题暂时无法验证。

### 16.2 统一工作流

```text
公开访谈 / 股东信 / 书籍摘录 / 用户粘贴文本
                         ↓
              来源与原文片段确认
                         ↓
               方法原则结构化拆解
                         ↓
             可检验假设与代理因子映射
                         ↓
               用户确认代理是否合理
                         ↓
                  FactorSpec V2
                         ↓
       传统评估 → 对抗式鉴证 → 可复现报告
```

### 16.3 MasterMethodSpec

| 字段 | 说明 |
|---|---|
| `method_id` | 方法包唯一标识 |
| `method_name` | 方法名称，不使用人格化Agent名称 |
| `source_title` | 公开来源标题 |
| `source_reference` | 链接、出版物或用户提供来源 |
| `source_excerpt` | 支撑该原则的原文片段 |
| `principles` | 方法原则列表 |
| `hypotheses` | 可检验假设列表 |
| `proxy_factors` | 每项假设对应的候选代理因子 |
| `proxy_grade` | 代理质量等级 |
| `data_requirements` | 所需字段及真实可用时间 |
| `limitations` | 无法覆盖的思想和数据限制 |
| `factor_specs` | 用户确认后生成的FactorSpec V2列表 |

### 16.4 代理质量等级

| 等级 | 含义 |
|---|---|
| A：直接代理 | 指标与原始命题关系直接，数据时点明确 |
| B：合理代理 | 能反映主要含义，但遗漏部分定性信息 |
| C：粗糙代理 | 只能反映局部特征，不能代表完整思想 |
| U：不可验证 | 当前数据不足或命题无法量化 |

代理等级描述的是“代理与思想的接近程度”，不是因子历史表现等级。

### 16.5 MVP方法包

MVP内置一个“巴菲特公开质量框架”方法包：

| 方法原则 | 候选代理 | MVP处理 |
|---|---|---|
| 资本回报 | ROE、ROIC | 有时点正确的财务数据时送检 |
| 盈利质量 | 经营现金流/净利润 | 有现金流与利润数据时送检 |
| 盈利稳定 | 毛利率或ROE滚动稳定性 | 需要多期财务数据 |
| 财务安全 | 资产负债率、利息保障倍数 | 有数据时送检 |
| 自由现金流估值 | 自由现金流/市值 | 数据完整时送检 |

所有名称必须表述为“巴菲特质量框架的候选代理”，不能命名为“巴菲特因子”或“巴菲特策略”。

如果财务数据权限不足，可以使用市盈率或市净率演示“粗糙估值代理”的传统评估与鉴证，但代理等级必须为C，并明确说明其不能替代自由现金流估值或完整质量框架。

### 16.6 MVP输入边界

- P0支持选择内置方法包；
- P0支持粘贴一段公开方法文本并生成草案；
- PDF自动解析和长文档检索属于P1；
- AI提取的来源片段必须由用户确认；
- 无法确认来源时只保存为“用户假设”，不能标记为大师公开观点。

### 16.7 验收标准

- 一个内置方法包可以完整打开和展示；
- 至少拆出5个方法原则及对应候选代理；
- 每个代理均显示代理等级、数据要求和局限；
- 至少一个数据可用的代理因子能够进入传统评估与鉴证流程；
- 数据不可用的代理显示“不可鉴证”，不生成伪结果；
- 页面不出现人格对话、模拟荐股或“大师策略收益”；
- AI不能生成没有来源支撑的直接引语。

## 17. 可复现凭证

### 17.1 凭证字段

- `run_id`；
- FactorSpec V2完整内容；
- 因子公式哈希或上传文件哈希；
- 数据快照清单及哈希；
- 股票池规则；
- 收益标签定义；
- 预处理和中性化配置；
- 压力测试配置；
- 随机种子；
- 引擎版本；
- 证据记录；
- 证据哈希；
- AI供应商和生成时间；
- 报告哈希。

### 17.2 哈希分层

- `evidence_hash` 只包含确定性输入、配置和计算结果；
- `report_hash` 包含AI解释和最终展示内容；
- 更换模型解释不应改变 `evidence_hash`；
- 修改因子、数据或测试参数必须改变 `evidence_hash`。

### 17.3 复现验收

在同一引擎版本和数据快照下重新运行：

- 确定性指标一致；
- 证据ID一致；
- `evidence_hash` 一致；
- AI文字允许不同，但不能改变证据结论。

## 18. 数据方案

### 18.1 P0所需数据

| 数据 | 用途 | 必要性 |
|---|---|---|
| 交易日历 | 日期对齐和收益标签 | 必须 |
| 股票基础信息 | 上市、退市和代码状态 | 必须 |

| 复权因子 | 处理公司行为 | 必须 |
| 历史总市值或流通市值 | 微盘剔除和市值中性化 | 核心Demo需要 |
| 历史PE、PB等估值字段 | 大师方法中的粗糙估值代理 | 大师Demo最低数据要求 |
| 停牌、ST、涨跌停 | A股专项质检 | 有则使用，否则披露限制 |
| 历史行业分类 | 行业矩阵和行业中性化 | P1 |
| 财务指标和三张报表 | 质量类代理因子 | 有权限则进入MVP |
| 财务公告日期 | 财务因子时点鉴证 | 财务代理得出结论前必须具备 |

### 18.2 数据源策略

- TuShare作为首选主数据源；
- 其他免费数据只能在许可明确、字段含义可核对时补充；
- 不为追求字段数量随意拼接多个口径不一致的数据源；
- 演示使用冻结的本地数据快照；
- 数据清单必须记录接口、拉取时间、日期范围、行数和文件哈希。

### 18.3 股票池构建

- 每个交易日依据上市日和退市日构建当时可用股票池；
- 禁止只使用当前仍上市股票回看历史；
- ST、停牌和上市天数规则按数据可用情况执行；
- 无法执行的过滤规则必须标记为“未测试”；
- 股票池变化规则写入复现凭证。

### 18.4 数据权限闸门

开发第一天验证以下数据是否可取：

- 日线行情；
- 复权因子；
- 历史市值；
- 历史PE、PB等估值字段；
- 上市和退市信息；
- 停牌、ST和涨跌停状态。
- 财务指标、报表和真实公告日期。

降级规则：

- 无历史市值：取消小微盘Demo，改为低流动性暴露；
- 无行业历史：不开发行业矩阵；
- 无ST和停牌：保留警告，不宣称通过相关质检；
- 无财务公告日期：质量类财务代理只展示方法拆解和数据缺口，不输出历史有效性结论；大师Demo改用C级估值代理展示完整流程。

## 19. 技术架构建议

### 19.1 MVP架构

```text
Streamlit + Plotly
        ↓
应用服务与Pydantic数据契约
        ↓
公式解析器
        ↓
因子计算引擎 ──→ 传统评估引擎 ──→ 鉴证与压力测试引擎
        ↓               ↓                  ↓
DuckDB / Parquet  Evaluation JSON    Evidence JSON
                                             ↓
                                       AI解释适配层
                                             ↓
                                  HTML / Markdown / JSON
```

### 19.2 技术选型

| 层 | 建议 |
|---|---|
| UI | Streamlit、Plotly |
| 数据处理 | pandas或Polars，MVP优先团队熟悉方案 |
| 统计 | NumPy、SciPy、statsmodels |
| 传统因子评估 | 优先复用 `alphalens-reloaded`，统一输出口径 |
| 公式解析 | Lark或同类正式解析器，不使用字符串eval |
| 数据存储 | Parquet + DuckDB |
| 数据契约 | Pydantic |
| 测试 | pytest |
| 模型接入 | 可配置的单一模型适配接口 |
| 导出 | Jinja2生成HTML/Markdown，JSON保存凭证 |

### 19.3 架构原则

- UI与核心计算逻辑分离；
- 传统评估结果和鉴证证据分层保存，不因新增鉴证逻辑破坏熟悉指标；
- 大师方法Skill只负责生成并确认MethodSpec，不另建一套计算引擎；
- 所有指标函数尽量保持纯函数；
- 压力测试共享同一个基线配置；
- 计算结果先写Evidence JSON，再由界面和AI消费；
- 演示数据和结果允许预计算缓存；
- 商业化阶段可在核心引擎外增加FastAPI，不在MVP提前建设。

## 20. 非功能需求

### 20.1 性能

- 三个问题因子Demo在本地缓存下60秒内完成或直接载入；大师方法Demo允许加载预计算结果；
- 普通单因子鉴证目标在3分钟内完成；
- 相同运行优先命中缓存；
- 页面不能因AI调用阻塞确定性结果展示。

### 20.2 稳定性

- AI失败不影响指标报告；
- 单项压力测试失败不影响其他结果；
- 数据不足时输出明确原因；
- 演示版本提供完整离线备份；
- 关键步骤写入运行日志。

### 20.3 安全与隐私

- 不执行上传文件中的代码；
- 上传文件只按CSV或Parquet数据解析；
- 限制文件大小和字段类型；
- API密钥只通过环境变量配置；
- AI只接收必要的证据摘要，不发送整份私有因子值数据。

### 20.4 可用性

- 桌面端优先，最低目标宽度为1280px；
- 重要结论不只依赖颜色表达；
- 指标必须提供口径提示；
- 失败、警告、未测试必须视觉区分；
- 用户不阅读说明文档也能完成三个Demo。

## 21. 四个核心Demo

### 21.1 Demo A：表现很好但存在未来数据穿越

**输入：** 包含负向位移或未来收益信息的因子公式。  
**预期现象：** 基线指标异常漂亮。  
**系统发现：** 公式依赖未来日期，时间正确性失败。  
**最终结论：** 无效，不继续评价收益表现。  
**演示价值：** 证明产品不会被漂亮曲线误导。

### 21.2 Demo B：名称不同但信息高度重复

**输入：** 普通20日收益与其对数单调变换。  
**预期现象：** 名称、公式写法和数值尺度不同。  
**系统发现：** 横截面排序和因子收益高度一致。  
**最终结论：** 疑似重复信息，新增独立信息有限。  
**演示价值：** 证明产品能识别“换名字的同一因子”。

### 21.3 Demo C：隐藏的小微盘暴露

**输入：** 在基线股票池中表现较好的候选因子。  
**预期现象：** 原始RankIC和分组表现较好。  
**系统发现：** 剔除微盘或市值中性化后显著衰减。  
**最终结论：** 脆弱或条件有效，主要依赖市值暴露。  
**演示价值：** 证明产品能够解释“为什么有效”。

Demo C的具体候选因子必须在真实数据取得后确定，不能为了展示效果编造统计结果。

### 21.4 Demo D：大师方法代理并不等于原始思想

**输入：** 选择“巴菲特公开质量框架”方法包。  
**预期现象：** 系统拆出资本回报、盈利质量、稳定性、财务安全和自由现金流估值五类假设。  
**系统发现：** ROE等指标只是可计算代理，无法完整代表长期竞争优势和管理层质量；部分代理受财务公告时点或数据权限限制。  
**最终结论：** 代理因子分别进入传统评估和鉴证，不能合并宣传为“大师策略”。  
**演示价值：** 证明大师方法是可审计的假设入口，而不是人格化荐股工具。

该Demo必须展示至少一个代理的完整传统评估 Tear Sheet，以及一个因数据或代理质量不足而被标记为“不可鉴证”的代理。

### 22.1 黑客松验收标准

## 28. 范围确认结论

本PRD建议将黑客松版本冻结为一个单用户、A股日频、以自动反事实测试和可复现证据为核心的因子验真工作台。

产品必须优先完成：

1. 一个标准化因子输入；
2. 一套完整的传统因子评估 Tear Sheet；
3. 四至五项高价值压力测试；
4. 一个证据化结论系统；
5. 一个可追溯来源、可评价代理质量的大师方法拆解 Skill；
6. 四个稳定且具有解释力的Demo。

在以上六项完成前，不启动任意Python执行、团队系统、完整财务因子库、更多大师方法包或大规模因子库建设。
